## 갱신 절차 (2달에 1번)

1. 새 엑셀을 이 폴더에 넣는다 (파일명 `YYYY.MM 요율표.xlsx` 형식 — 연월이 화면 상단과
   "N월 변동" 탭 이름에 쓰인다). 예전 파일은 둬도 된다 — **수정 시각이 가장 최근인** 파일을 쓴다.
2. `python build.py` → `요율표.html` 생성. 출력에 행 수와 제조형태·포장정보 매칭 건수가 나온다.
   새 엑셀이면 포장정보를 식약처 API에서 다시 받느라 **10분 남짓** 더 걸린다(진행 상황이 50페이지마다 출력됨).
3. ~~`요율표.html`을 Artifact 링크에 다시 게시~~ — **2026-10-20부터 하지 않는다.** Artifact 링크는 "링크가 있는
   누구나" 공개 상태라 요율표를 다시 올리면 PWA의 코드·기기 보안이 무력화된다. `요율표.html`은 이 PC에서
   확인용으로만 생성된다.
4. **PWA 데이터 올리기**: `cd pwa && python admin.py upload-data` → 앱을 다음에 열 때 새 데이터를 받는다
   (앱 재설치 불필요).
5. 코드가 바뀌었으면 커밋·푸시.

### 엑셀 구조 전제

- **첫 시트**: `성분명`으로 시작하는 머리글 행 아래 데이터. 열 순서 고정 —
  A 성분명, B 코드(=요율), C 제약사명, D 생동/생산, E 품목명, F 약가, G 오리지날/대조약,
  H 보험코드, I 특이사항.
- **둘째 시트**(이달 특이사항): "9월 신제품 및 재출시" / "9월 요율변동" / "9월 약가변동"처럼
  제목 한 칸짜리 행 → 머리글 행 → 데이터, 구간 사이는 빈 행. 머리글에 `변경 전`이 있으면
  변동 목록(전→후)으로, 아니면 품목 카드로 표시.
- 열 순서나 시트 구성이 바뀌면 `build.py`의 `read_main`/`read_special`을 고쳐야 한다.

## 데이터 처리 규칙

- **I열 특이사항은 싣지 않는다** (둘째 시트의 특이사항 열도 제거).
- **D열(생동/생산)은 엑셀 값을 쓰지 않는다.** H열 보험코드로 Druginform 서버 DB
  (`/opt/drugapp/drugs.db`)를 **읽기 전용**(`mode=ro`)으로 조회해 `자체생산` /
  `위탁생산 · 위탁업체명`으로 바꿔 넣는다. 없으면 화면에 "제조형태 확인불가".
  - 엑셀 D열과 DB는 약 11%(2026.09 기준 738건) 어긋난다 — DB(식약처 허가 기준)를 따른다.
  - 보험코드 앞에 `D`가 붙은 행(예: `D628800250`)은 같은 품목을 다른 유통채널(파트너스 등)로
    한 번 더 적은 것 → `D`를 떼고 조회.
  - 서버 접속(`ssh root@1.234.80.8`)이 안 되면 직전 사본 `druginform_mfg.json`을 쓴다.
  - 2026.09 기준 10,557행 중 9,602행 매칭.
- **포장정보**: 의약품안전나라 제품정보 하단 "포장정보"와 같은 값. 식약처 제품허가 **상세** API
  (`DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnDtlInq08`)의 `PACK_UNIT`을 `EDI_CODE`(보험코드)로 맞춘다.
  카드에 `포장 30정/병` 태그로 표시(여러 개면 `, `로 구분).
  - 목록 API(`getDrugPrdtPrmsnInq08`)에는 `PACK_UNIT`이 없어서 상세 API를 100건씩 전체 페이지(약 450페이지,
    페이지당 약 1MB) 조회한다 → 10분 남짓.
  - API 키는 **Druginform 서버의 `.env`를 서버에서 읽어 쓰기만** 한다(`ssh`로 조회 스크립트를 보내 실행,
    서버에 파일을 남기지 않음). 이 PC `Druginform/.env`의 키는 "등록되지 않은 서비스키" 오류가 난다.
  - `druginform_pack.json`이 엑셀보다 새것이면 API를 다시 부르지 않고 사본을 쓴다(새 엑셀이 오면 자동 재조회).
    조회 실패 시 이전 사본, 사본도 없으면 포장정보 없이 만든다.
  - 허가취하 품목과 보험코드가 겹치면 정상 품목 값을 우선. 보험코드 앞 `D`는 떼고 조회.
  - 2026.09 기준 10,557행 중 9,637행 매칭.
- **Druginform 앱은 데이터 출처일 뿐, 이 작업 때문에 앱 코드·DB·서버 파일을 고치지 않는다.**

## 화면 기능

- **전체 검색**: 성분·품목·제약사·대조약·보험코드 통합 검색(띄어쓰기로 여러 단어 AND,
  대소문자·공백 무시) + **제약사(C열) 거르기 칸** + 정렬(기본순/코드↓/약가↓).
  50건씩 "더 보기". 성분 칩을 누르면 같은 성분 전체 비교.
- **생산형태 필터** (PWA만, 2026-10-20): 검색창 아래 [전체]/[자체생산]/[위탁생산] 칩. 검색어·제약사와 AND.
  제조형태 확인불가 품목은 필터를 고르면 빠짐(2026.09 기준 자체 3,170 / 위탁 6,432 / 전체 10,557).
- **N월 변동** 탭: 둘째 시트 내용. 요율·약가 변동 항목을 누르면 그 품목 검색.
- **★ 즐겨찾기** 탭 (PWA만, 2026-10-20): 카드 이름 옆 ☆/★로 추가·해제, 최근 추가 순. **폰마다 localStorage
  (`mr-favs`)에만 저장**(폰 바꾸거나 앱 삭제 시 사라짐). 키는 보험코드(`e:<H열 값>`, D 붙은 유통채널 행도 구분,
  보험코드 없으면 `n:제약사|품목명`)라 2달마다 데이터가 바뀌어도 유지·새 값으로 표시. 새 요율표에 없는 항목은
  "N개는 이번 요율표에 없어요 [정리]" 안내.
- 마지막 탭·검색어·제약사·정렬·생산형태 필터는 브라우저(localStorage)에 기억.
- 라이트/다크 모드 대응.

## PWA 앱 (`pwa/`)

- **주소**: https://mine-rate.mine-pharm.workers.dev (Cloudflare 계정의 workers.dev 하위 이름 `mine-pharm`
  — `mine`은 이미 사용 중이라 불가했음)
- **구성**: Cloudflare Workers(무료) 하나에 정적 화면(`public/`) + API(`src/worker.js`).
  - **D1** `mine-rate-db`의 `codes` 표(`schema.sql`): 코드별 이름·사용 여부·등록 기기·첫 등록/마지막 접속.
    id = 코드 원문의 SHA-256 (서버에 코드 원문 없음).
  - **KV** `RATE_KV`: `data`(요율 데이터 JSON 약 1.9MB). 버전(etag)은 **같은 키의 metadata**(`{"etag": ...}`)로
    함께 올린다 — 예전처럼 `data:etag` 키를 따로 두면 KV 지역 반영 지연 때 "새 버전 + 옛 데이터"가 섞여 앱이
    옛 데이터를 최신으로 착각할 수 있어 2026-10-20에 합침(`data:etag` 키 삭제).
  - 비밀값 `TOKEN_SECRET`(토큰 서명키)은 `wrangler secret`으로만 등록(파일에 없음).
- **접속 흐름**: 코드 + 앱이 만든 무작위 기기 ID → `/api/activate` → 토큰 발급(HMAC). `/api/data`는 토큰
  확인 + D1에서 사용 여부·기기 일치 확인 후 데이터 전달(같은 버전이면 304). 폰이 압축 응답을 받으면 Cloudflare가
  etag를 `W/"..."`로 바꿔 보내므로 `W/`를 떼고 비교한다. 데이터는 KV에서 stream으로 그대로 흘려보낸다(무료 플랜
  CPU 10ms 제한 대비). 기기 초기화된 코드의 옛 토큰에는 "기기 등록이 초기화됐어요" 안내(`error: reset`). 앱은 받은 데이터를 기기 안 캐시에
  보관해 오프라인에서도 보이고, 열 때마다 새 버전만 확인.
- **기기 1대 고정**: 첫 등록 기기에 묶음. 첫 등록 후 **10분 안 1회 이동** 허용(아이폰 사파리→홈 화면 앱 대비).
  등록은 D1 조건부 UPDATE(`WHERE device IS NULL` 등)라 동시에 여러 기기가 와도 하나만 성공.
  - 처음엔 KV에 코드 기록을 뒀는데 **KV는 쓰기 반영이 최대 1분 늦어** 실서버 시험에서 세 번째 기기가 끼어듦 →
    D1로 옮겨 해결(실서버 동시 5대 시험: 1대만 성공).
  - 10분 이동 여유 제거, 코드 오입력 횟수 제한은 검토했으나 **사용자 결정으로 넣지 않음**(2026-10-17).
- **아이폰·카톡 대응**: 아이폰 사파리(홈 화면 앱이 아닐 때)는 코드 입력 대신 "먼저 홈 화면에 추가" 안내,
  카톡 등 인앱 브라우저는 "브라우저로 열기"(`kakaotalk://web/openExternal`) 안내. 안드로이드는 "앱 설치" 줄.
- **설치 안내 그림**: `public/install.html` → https://mine-rate.mine-pharm.workers.dev/install (아이폰 5단계·
  안드로이드 4단계, 단순화한 폰 그림에 누를 곳을 주황 테두리로). 코드 입력·아이폰 안내 화면에 "설치 방법 그림으로
  보기" 링크. 같은 내용을 `pwa/guide/아이폰_설치안내.png`, `안드로이드_설치안내.png`로 렌더해 카톡 전송용으로 둠
  (`/install?os=ios|android`를 폰 크기로 캡처, 탭·돌아가기 링크는 숨김). 실제 화면 캡처가 아닌 그림이라 OS·앱
  버전에 따라 메뉴 이름·위치가 다를 수 있음.
- **배너**: `public/banner.json`의 `items: [{image, url, start?, end?, alt?}]`, 이미지는 `public/banners/`.
  비어 있으면 숨김, 여러 개면 5초마다 넘김, 터치하면 새 창(브라우저)으로 주소 열기. 권장 크기 1200×300.
  사용자가 이미지·주소를 주면 Claude가 넣고 `python admin.py deploy`.
- **관리 (`pwa/admin.py`, 이 PC에서 `npx wrangler login` 된 상태 필요)**
  - `add "김은경 대표" --code 123123` (코드 지정) / `add 이름` (무작위 8자리 영숫자)
  - `list` (상태·기기 등록·첫 등록·마지막 접속), `code 이름`, `reset 이름`(폰 바꿈),
    `stop`/`start 이름`, `delete 이름`, `import`(codes.csv → D1 재등록), `upload-data`, `deploy`
  - `--local` 붙이면 `npx wrangler dev --local`용 시험 저장소에 적용 (`.dev.vars`에 시험용 TOKEN_SECRET)
  - Cloudflare 로그인 토큰이 만료된 직후 첫 요청이 7403(권한 없음)으로 실패하는 일이 반복돼, 7403이면 한 번 자동 재시도.
- **코드 백업**: `codes.csv`(코드 원문)는 이 PC에만 있고 서버엔 해시뿐이라, 잃으면 누구에게 무슨 코드를 줬는지
  복구 불가 → 두 겹으로 백업(2026-10-19 사용자 결정 A+B).
  - **A. 암호화해서 GitHub에**: `codes.csv.enc`. RSA-3072로 감싼 AES-256-GCM. 잠그는 열쇠(`backup_public.pem`)만으로
    백업되므로 `add`·`delete` 때 비밀번호 없이 자동 갱신 → 커밋·싱크하면 GitHub에 올라감. 여는 열쇠
    (`backup_private.pem.enc`)는 백업 비밀번호로 잠김. 복원: `python admin.py restore`(비밀번호 입력, 기존
    codes.csv가 있으면 `codes.restored.csv`로). 비밀번호 설정은 `backup-setup`(사용자가 VS Code 터미널에서 직접).
  - 백업 비밀번호는 사용자가 보관(요청에 따라 Claude 메모리에도 기록, 저장소에는 없음). 짧고 흔한 비밀번호라
    저장소 접근자는 열 수 있음을 안내함 — 더 긴 비밀번호로 바꾸려면 두 `.pem` 파일을 지우고 `backup-setup` 재실행.
  - **B. 사용자가 직접**: `codes.csv`를 개인 클라우드·USB에 복사. 코드 발급·삭제 뒤에는 다시 복사 필요.
- **발급 현황 (2026-10-20)**: `관리자 시험`(사용자 본인 폰, 10-20 등록 — 앱 동작 확인용으로 유지 권장),
