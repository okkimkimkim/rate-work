# 요율표 검색 웹앱 (마인약품)

2달마다 받는 요율표 엑셀을 스마트폰에서 검색하기 쉬운 웹페이지 한 장으로 바꾼다.

- **웹앱 링크**: https://claude.ai/artifact/3HvyZw8Qf1EfgSfVz8Hm4i
  (Claude Artifact. 화면 제목 "마인약품". 2026-10-07 기준 공유 범위 "링크가 있는 누구나" —
  요율이 보이는 페이지라 링크 관리에 주의)
- **저장소**: https://github.com/okkimkimkim/rate-work (private)

## 파일

| 파일 | 역할 | git |
|---|---|---|
| `build.py` | 최신 엑셀 → `요율표.html` 생성 | O |
| `template.html` | 화면(HTML/CSS/JS). `/*__DATA__*/null` 자리에 데이터가 들어간다 | O |
| `*.xlsx` | 원본 요율표 엑셀 | **X** (영업 기밀) |
| `요율표.html` | 생성 결과물 (요율 포함) | **X** |
| `druginform_mfg.json` | Druginform 서버에서 받은 보험코드→제조형태 사본 | **X** |
| `druginform_pack.json` | 식약처 API에서 받은 보험코드→포장단위 사본 | **X** |

## 갱신 절차 (2달에 1번)

1. 새 엑셀을 이 폴더에 넣는다 (파일명 `YYYY.MM 요율표.xlsx` 형식 — 연월이 화면 상단과
   "N월 변동" 탭 이름에 쓰인다). 예전 파일은 둬도 된다 — **수정 시각이 가장 최근인** 파일을 쓴다.
2. `python build.py` → `요율표.html` 생성. 출력에 행 수와 제조형태·포장정보 매칭 건수가 나온다.
   새 엑셀이면 포장정보를 식약처 API에서 다시 받느라 **10분 남짓** 더 걸린다(진행 상황이 50페이지마다 출력됨).
3. `요율표.html`을 **같은 Artifact 링크에 다시 게시**한다 (Claude Code에서 "요율표 갱신해줘").
   링크가 그대로라 폰 홈 화면 바로가기를 다시 만들 필요 없음.
4. 코드가 바뀌었으면 커밋·푸시.

### 엑셀 구조 전제

- **첫 시트**: `성분명`으로 시작하는 머리글 행 아래 데이터. 열 순서 고정 —
  A 성분명, B 코드(=요율), C 제약사명, D 생동/생산, E 품목명, F 약가, G 오리지날/대조약,
  H 보험코드, I 특이사항.
- **둘째 시트**(이달 특이사항): "9월 신제품 및 재출시" / "9월 요율변동" / "9월 약가변동"처럼
  제목 한 칸짜리 행 → 머리글 행 → 데이터, 구간 사이는 빈 행. 머리글에 `변경 전`이 있으면
  변동 목록(전→후)으로, 아니면 품목 카드로 표시.
- 열 순서나 시트 구성이 바뀌면 `build.py`의 `read_main`/`read_special`을 고쳐야 한다.

## 데이터 처리 규칙

- **I열 특이사항은 싣지 않는다** (둘째 시트의 특이사항 열도 제거).
- **D열(생동/생산)은 엑셀 값을 쓰지 않는다.** H열 보험코드로 Druginform 서버 DB
  (`/opt/drugapp/drugs.db`)를 **읽기 전용**(`mode=ro`)으로 조회해 `자체생산` /
  `위탁생산 · 위탁업체명`으로 바꿔 넣는다. 없으면 화면에 "제조형태 확인불가".
  - 엑셀 D열과 DB는 약 11%(2026.09 기준 738건) 어긋난다 — DB(식약처 허가 기준)를 따른다.
  - 보험코드 앞에 `D`가 붙은 행(예: `D628800250`)은 같은 품목을 다른 유통채널(파트너스 등)로
    한 번 더 적은 것 → `D`를 떼고 조회.
  - 서버 접속(`ssh root@1.234.80.8`)이 안 되면 직전 사본 `druginform_mfg.json`을 쓴다.
  - 2026.09 기준 10,557행 중 9,602행 매칭.
- **포장정보**: 의약품안전나라 제품정보 하단 "포장정보"와 같은 값. 식약처 제품허가 **상세** API
  (`DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnDtlInq08`)의 `PACK_UNIT`을 `EDI_CODE`(보험코드)로 맞춘다.
  카드에 `포장 30정/병` 태그로 표시(여러 개면 `, `로 구분).
  - 목록 API(`getDrugPrdtPrmsnInq08`)에는 `PACK_UNIT`이 없어서 상세 API를 100건씩 전체 페이지(약 450페이지,
    페이지당 약 1MB) 조회한다 → 10분 남짓.
  - API 키는 **Druginform 서버의 `.env`를 서버에서 읽어 쓰기만** 한다(`ssh`로 조회 스크립트를 보내 실행,
    서버에 파일을 남기지 않음). 이 PC `Druginform/.env`의 키는 "등록되지 않은 서비스키" 오류가 난다.
  - `druginform_pack.json`이 엑셀보다 새것이면 API를 다시 부르지 않고 사본을 쓴다(새 엑셀이 오면 자동 재조회).
    조회 실패 시 이전 사본, 사본도 없으면 포장정보 없이 만든다.
  - 허가취하 품목과 보험코드가 겹치면 정상 품목 값을 우선. 보험코드 앞 `D`는 떼고 조회.
  - 2026.09 기준 10,557행 중 9,637행 매칭.
- **Druginform 앱은 데이터 출처일 뿐, 이 작업 때문에 앱 코드·DB·서버 파일을 고치지 않는다.**

## 화면 기능

- **전체 검색**: 성분·품목·제약사·대조약·보험코드 통합 검색(띄어쓰기로 여러 단어 AND,
  대소문자·공백 무시) + **제약사(C열) 거르기 칸** + 정렬(기본순/코드↓/약가↓).
  50건씩 "더 보기". 성분 칩을 누르면 같은 성분 전체 비교.
- **N월 변동** 탭: 둘째 시트 내용. 요율·약가 변동 항목을 누르면 그 품목 검색.
- 마지막 탭·검색어·제약사·정렬은 브라우저(localStorage)에 기억.
- 라이트/다크 모드 대응.

### 2026-10-14 — 앱 형태 검토 (결정 대기)

지금 웹앱은 Claude Artifact라 claude.ai 안에서만 열린다. 앱처럼 쓰려면 직접 올릴 곳이 필요해서
선택지를 정리했다. **아직 결정 안 됨** — 사용자에게 받아야 할 답: 누가 쓰는지(본인/직원/파트너),
안드로이드·아이폰 여부, 어디에 올릴지.

- **PWA (추천)**: 홈 화면 설치 시 주소창 없는 전체화면, 오프라인 검색, 갱신 자동 반영,
  안드로이드·아이폰 모두. **HTTPS 필수**(IP만으로는 사실상 불가) → 새 도메인 구매는 불필요하고
  아래 중 하나로 주소를 마련:
  - **Cloudflare Pages + Cloudflare Access** (`*.pages.dev`, 무료, 서버 불필요, 허용 이메일만 로그인 —
    50명까지 무료). 소수 사용자용으로 가장 간단. Cloudflare 계정 필요.
  - **기존 도메인 하위 주소** (`rate.druginform.kr` / `rate.마인약품.com`, 카페24 서버·DNS 한 줄 +
    인증서). 로그인(비밀번호)은 직접 구현해야 함. Druginform 앱과는 분리된 별도 페이지로.
  - GitHub Pages는 공개라 요율 자료에 부적합.
- **안드로이드 APK** (데이터 내장): 도메인·서버 불필요, 완전 오프라인, 파일로 배포. 아이폰 불가,
  2달마다 새 APK 재설치. TWA 방식(Druginform처럼)은 도메인 필요.
- 스토어 정식 출시는 내부 자료라 부적합.
- 어느 방식이든 요율이 들어 있으므로 **로그인/접근 제한 필수**.
